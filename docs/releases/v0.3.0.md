# Subagent Bridge 0.3.0 — macOS and CLI preview

Use other coding agents as subagents—without leaving your own.

## What's new

- Settings now separates an agent's ability to orchestrate from its ability to work as a subagent. Expand a row for setup guidance, installed versions, and model discovery.
- Existing installation state remains visible during refresh. Failed discovery keeps the previous model catalog and does not disable saved rules.
- The pinned acpx registry supplies 27 catalog entries, including Bridge's DeepSeek integration. 25 have installed-launch recipes; two are catalog-only. These are candidates, not 27 live-tested integrations. Bridge does not download or run fallback adapters automatically.
- A standalone Node CLI shares the desktop app's applied rules and saved drafts. Edit, import, export, validate, preview, and apply without opening the app. Revision checks and recovery files protect concurrent edits.
- Optional configuration MCP setup stays out of the way. Custom task names and advanced prompt-preview controls remain available in Settings.

## Downloads

- **Subagent-Bridge_0.3.0_arm64.dmg** — macOS Apple Silicon, macOS 12+. Requires Node.js 22.13+ and separately installed/configured harnesses.
- **subagent-bridge-local-0.3.0.tgz** — CLI package. Install from its download folder with `npm install --global ./subagent-bridge-local-0.3.0.tgz`. Requires Node.js 22.13+. Not published to the npm registry.
- **SHA256SUMS** — checksums for the packages above.

The macOS preview is **ad-hoc signed, not Developer ID signed or notarized**. Read the [installation guide](https://github.com/Tarachand-Gupta/subagent-bridge/blob/v0.3.0/docs/install-macos.md) before first launch. Windows/Linux desktop installers and Intel macOS installers are not included. CLI regression tests do not establish native Windows/Linux harness integration acceptance.

## Upgrade and shared configuration

Keep `~/.harness-bridge` intact. Applied rules remain in `config.json`; desktop Save Rules and CLI edit/import share `editor-draft.json`. No migration or renamed data folder is required. Existing `harness-bridge` commands and integration identifiers remain compatible.

Install to a stable location. Apply Rules or `subagent-bridge config apply` can update native integration paths; then follow the displayed reload/restart or Codex hook-review instructions. Keep the prior runtime available until its running work finishes and the updated connection works. The CLI's default edit/import saves a draft; legacy `config save` still applies immediately.

## Coverage and limits

Codex, Pi, OpenCode, and the pinned DeepSeek build retain native parent integrations. Claude Code remains deferred. Additional registry entries require installed launchers, successful capability discovery, and per-version live acceptance. Hermes is planned, not shipped in the registry.

Workers keep their own providers, credentials, tools, and permissions. Parent sessions pass their current project folder and relevant task context; full parent chat history is not copied automatically. Same-worker follow-ups retain context while the owning worker service remains alive. Codex completion is delivered during active turns or on the next turn; an idle desktop chat is not woken. Work is never silently replayed after an unknown outcome.
